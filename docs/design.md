# 支払い準備・資金移動管理

毎月の口座振替・振込に備えて、必要金額と口座残高を確認し、
「どの口座に、いくら準備すればよいか」を把握するためのAppSheetアプリ。

Googleスプレッドシートをデータ基盤として使用する。

## 目的

これまでExcelや紙で行っていた、

- 今月の請求額の確認
- 請求書・明細を確認したかのチェック
- 口座ごとの必要金額の集計
- 現在残高の確認
- 不足金額の把握
- 必要な資金移動

をAppSheetで管理する。

家計簿そのものを作ることが目的ではない。
MoneyForwardなどは資産・家計全体の把握に引き続き利用し、
このアプリは「支払い前の準備」に特化する。


## 基本的な考え方

### 支払いの確認

毎月発生する支払いを一覧化する。

固定額は支払先マスターから初期値を利用し、
カードなどの変動額は当月の請求額を入力する。

各支払いについて、

- 金額確認済み
- 今月は支払いなし

を記録できるようにする。

最終的には、

「確認済み 12 / 15」
「未確認 3件」

のように、未確認件数をすぐ確認できる画面を作る。


### 給料日前と給与入金後

給与日は28日。

支払い準備では単純な1か月単位だけでなく、
「どの給与から準備する支払いか」を意識する。

例：

- 26日・27日の支払い → 給料日前に準備
- 28日の給与入金後に準備する支払い → 給与入金後

10月2日の引落でも、
9月28日の給与から準備するものは「給与入金後」の準備対象となる。

そのため、

「支払月」
と
「準備するタイミング」

は別の概念として管理する。


## データ構成

AppSheetでは以下の5テーブルを使用。

### 1. 月次支払い

実際の各月の支払いデータ。

主な項目：

- 月次支払ID
- 対象年月
- 支払先ID
- 支払先名控え
- 実際の引落日
- 実際の口座ID
- 会計区分
- 今月の金額
- 確認済み
- 今月なし
- 準備ID
- 支払方法
- 支払回次
- 引落・出金済日時
- 生成識別子
- 備考

支払先マスターの情報を基本とするが、
当月だけ金額・日付・口座などを変更できるようにする。


### 2. 支払先マスター

通常の支払い条件を管理。

例：

- 住宅ローン
- クレジットカード
- 水道
- 保険
- 学費
- 仕送り
- 積立
- 小遣い

主な項目：

- 支払先ID
- 支払先名
- 通常口座ID
- 通常引落日
- 月末扱い
- 通常金額
- 金額区分
- 支払パターン
- 支払方法
- 会計区分
- 通常準備区分
- 使用状態


### 3. 口座マスター

支払い・資金移動に使用する口座を管理。

主な項目：

- 口座ID
- 口座表示名
- 銀行名
- 名義
- 会計区分
- 役割・備考
- 使用状態

名義と会計区分は別々に管理する。

現在は、

- ショウタロウ名義 → 主に家計
- 友紀子名義 → 主に友紀子個人

としている。

口座番号・ログインID・パスワードなどの
機密情報は保存しない。


### 4. 口座残高

口座残高の確認履歴。

残高を上書きするのではなく、
確認するたびに履歴として追加する。

主な項目：

- 残高ID
- 準備ID
- 口座ID
- 会計区分控え
- 確認日時
- 現在残高
- 備考


### 5. 準備管理

「いつの支払い準備か」をまとめる単位。

主な項目：

- 準備ID
- 準備対象月
- 準備区分
- 会計区分
- 一覧作成済み
- 備考

## 2026-09-27 作業記録

### 今日やったこと

AppSheetの入力画面を、実際の支払い準備の流れに合わせて整理した。

#### 準備管理を入力の起点に変更

- 準備管理をメインの画面に配置
- 準備管理のDetailから「支払いを追加」Actionで月次支払いFormを開く形にした
- 準備IDはActionから自動で引き継ぐ
- 月次支払いFormでは準備IDそのものを見せず、準備内容を確認用に表示する
- 準備年月の初期値を「翌月1日」に変更
  - `EOMONTH(TODAY(), 0) + 1`
- 例：9月末に作業する場合は「2026年10月分」として準備する

#### 「○月分」と実際の支払日の考え方

PayFlow上の「10月分」は、単純なカレンダー月ではなく、次の給与サイクルに向けて準備する支払いのまとまりとして扱う。

例：

- 9/26 → 10月分
- 9/27 → 10月分
- 10/2 → 10月分
- 10/10 → 10月分

通常引落日が26日・27日の場合は準備年月の前月、それ以外は準備年月と同じ月の日付を初期値として設定する。

`実際の引落日` はInitial valueで自動入力し、必要な場合は手修正できるようにする。
また、支払先変更時に再計算されるよう `Reset on edit?` を利用する。

#### 支払先マスター・入力順

支払いを実際の確認順に入力しやすくするため、支払先マスターに `入力順` を追加。

基本順：

1. 26日
2. 27日
3. 2日
4. 10日
5. 随時（通常引落日なし）

入力順はApp formulaで設定。

```appsheet
SWITCH(
  [通常引落日],
  26, 1,
  27, 2,
  2, 3,
  10, 4,
  5
)
```

支払先Refの候補は `ORDERBY()` で入力順を利用する。

また、支払先マスターに表示用の名前を作り、

- 楽天カード（27日）
- 住宅ローン（10日）
- 固定資産税（随時）

のように、支払先名と通常引落日を一緒に確認できるようにした。

#### 月次支払いFormの自動入力

支払先を選択すると、支払先マスターを参照して以下を自動入力する方針。

- 実際の口座
- 会計区分
- 実際の引落日
- 固定額の場合の今月の金額
- その他、支払先ごとに決まっている情報

固定額の今月金額はInitial valueで設定し、その月だけ金額が違う場合は手修正できるようにする。

```appsheet
IF(
  [支払先ID].[金額区分] = "固定",
  [支払先ID].[通常金額],
  ""
)
```

#### 月次支払いFormの整理

毎月の入力時に人が確認・変更する項目を中心にし、普段触らない項目はFormから外した。

Formで主に扱う項目：

- 支払先
- 実際の引落日
- 実際の口座
- 今月の金額
- 確認済み
- 今月なし
- 備考

以下はデータとして必要に応じて保持するが、通常Formでは非表示とする。

- 準備ID
- 会計区分
- 支払方法
- 支払回次
- 引落・出金済日時
- 生成識別子

Form上部には、

`2026年10月分｜給料日前｜家計`

のような準備内容を確認用に表示する。

## 次にやること（2026-09-27時点）

### 1. 準備管理に「準備表示名」を作る

`2026年10月｜給料日前｜家計` のように、準備内容が一列で分かる表示名を作る。

準備管理側のLabelとして利用し、Detail・Ref・月次支払いFormなどで同じ表示を再利用できるようにする。

### 2. 金融機関ごとの支払い集計

その月の支払いを金融機関・口座ごとにまとめ、

- その口座から支払う明細
- 口座ごとの必要額合計

が分かる画面を作る。

まずは `実際の口座ID` を使ったGroup byを検討し、必要に応じてSliceやVirtual Columnを追加する。

### 3. 口座残高まわりを整える

準備時点の口座残高を入力し、支払いに必要な金額と比較できるようにする。

目標：

- 各口座の現在残高
- 今回必要な金額
- `現在残高 - 必要額`
- 不足している場合の必要入金額
- 残高未確認の口座が分かる表示
- 残高確認履歴を残す

最終的に「どの口座へ、あといくら移動すればよいか」が一目で分かる画面を目指す。
